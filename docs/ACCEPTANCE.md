# 手工验收清单（v1）

> 用途：v3.0 重写的回归闸门。每阶段末（阶段 1 / 2 / 3）逐条跑一遍，任一条失败即阶段未验收。
> 维护：只增不删。若某条因设计变更而不再适用，标注 `N/A` 并写明原因，不要直接删除。

## 执行方式

- 设备：API 29+ 真机或模拟器，安装当阶段的 Release APK。
- 每条记录：`通过 / 失败 / N/A`。失败必须附截图或 logcat 片段。
- 涉及"不闪退"的条目，判定标准是**进程存活**（`adb shell pidof` 仍返回 PID），不是"看起来没崩"。

## K. 交互与输入（11 条，真机反馈补充）

| # | 操作 | 期望 |
|---|---|---|
| K01 | 打开设置与历史页，注意顶部标题按钮 | 按钮完整落在状态栏以下，不与状态栏文字重叠、不被系统手势抢走点击 |
| K02 | 输入 `12+34`，点算式里 `+` 之前，按 ⌫ | 删掉的是 `2`（光标左侧字符），算式变 `1+34`，光标停在 `+` 之前并显示竖线 |
| K03 | 光标停在算式中间时按数字键 | 数字插在光标处，不是接在末尾 |
| K04 | 任意算出一条结果后按 AC | 表达式、结果、错误提示**同时清空**，结果区回到 `0` |
| K05 | 计算 `sin(1)` | 结果右侧**不出现** `S⇔D`（该结果没有分数形态） |
| K06 | 计算 `1/3`，点 `S⇔D`；再算 `2+3` 看是否有该按钮 | `1/3` 在小数 `0.3333333333333333` 与真分式 `1/3` 之间来回切；`2+3` 的结果 `5` 没有该按钮 |
| K07 | 科学模式观察函数区；矩阵模式算 `[[1,2],[3,4]]` 的逆 | 17 个函数键折成 **3 行**（6/6/5）全部可见、无需横向滑动，且每行末尾不留半截空键；逆显示为 `−2, 1; 3/2, −1/2`（真分式，不是 `0.5`/`1.5`） |
| K11 | 矩阵模式某单元格输入 `abc`，再按「计算」 | 输入框只保留数字字符；若确实无法解析（如只填 `-`），结果区给出「矩阵里有无法识别为数字的单元格」而不是毫无反应 |
| K08 | 设置里把显示模式改成「精确分数」，回计算器算 `1/3` | 结果**直接**是真分式，不需要点 `S⇔D`（验证设置真的送达求值层） |
| K09 | 算 `1/3` 后旋转屏幕（或按 Home 放置一段时间后返回） | 算式与结果都还在，结果不是 `0` |
| K10 | 打开设置页底部 | 版本号形如 `3.0 (7)`，`versionCode` 与实际安装包一致，便于核对验收的是哪一版 |

## 与自动化测试的分工

| 层 | 归属 | 说明 |
|---|---|---|
| `:core:math` 参数化单测 | 自动化 | 覆盖 A01–A08、B01–B07、C02–C04、D01–D05、E01–E05 的计算侧，以及精确分数与函数库 |
| `:feature:calculator` 单测 | 自动化 | 覆盖矩阵形状推导（E06 的规则部分）与状态转换 |
| `:core:mathui` compose 测试 | **未落地** | 需要设备/模拟器，本地环境不具备 |
| 本清单 | **手工** | 覆盖进程存活、视觉残留、启动白闪、图标、数据库升级 —— 这些自动化不经济或无法在本地执行 |

本清单不替代自动化测试；自动化测试失败不进入手工验收环节。
